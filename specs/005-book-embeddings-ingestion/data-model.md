# Data Model: Book Embeddings Ingestion

## Overview
This document defines the data models for the book embeddings ingestion system, including entities, their attributes, relationships, and validation rules.

## Entity: BookContent
Represents the text content extracted from book URLs, including metadata such as source URL, page/chapter information, and content structure.

### Attributes:
- `id` (string): Unique identifier for the book content
- `source_url` (string): The original URL from which the content was extracted
- `title` (string): Title of the book or document
- `author` (string): Author of the book (if available)
- `language` (string): Language of the content (e.g., "en", "es")
- `content` (string): The raw text content extracted from the book
- `created_at` (datetime): Timestamp when the content was first ingested
- `updated_at` (datetime): Timestamp when the content was last updated
- `page_count` (integer): Number of pages in the book
- `word_count` (integer): Total word count of the book

### Validation Rules:
- `source_url` must be a valid URL format
- `content` must not be empty
- `page_count` must be a positive integer
- `word_count` must be a non-negative integer

## Entity: TextChunk
Represents a segment of book content that has been cleaned and prepared for embedding, with associated metadata like source location and chunk ID.

### Attributes:
- `id` (string): Unique identifier for the text chunk
- `book_content_id` (string): Reference to the parent BookContent
- `chunk_index` (integer): Sequential index of this chunk within the book
- `content` (string): The cleaned text content of this chunk
- `source_url` (string): URL where this chunk originated
- `source_location` (string): Specific location within the book (e.g., "Chapter 3, page 45")
- `token_count` (integer): Number of tokens in the chunk
- `created_at` (datetime): Timestamp when the chunk was created
- `metadata` (object): Additional metadata associated with the chunk

### Validation Rules:
- `content` must not exceed the maximum token limit for the embedding model
- `chunk_index` must be a non-negative integer
- `token_count` must be positive
- `book_content_id` must reference an existing BookContent

## Entity: EmbeddingVector
Represents the numerical vector representation of a text chunk, generated by the Cohere model, with associated metadata and reference to the source chunk.

### Attributes:
- `id` (string): Unique identifier for the embedding
- `text_chunk_id` (string): Reference to the source TextChunk
- `vector` (array[float]): The embedding vector (e.g., 1024-dimensional array)
- `model_name` (string): Name of the model used to generate the embedding
- `model_version` (string): Version of the model used
- `created_at` (datetime): Timestamp when the embedding was generated
- `embedding_size` (integer): Dimension of the embedding vector

### Validation Rules:
- `vector` must have the correct dimensions for the specified model
- `text_chunk_id` must reference an existing TextChunk
- `model_name` must be a valid Cohere model name
- `embedding_size` must match the actual vector length

## Entity: VectorDatabaseRecord
Represents an entry in Qdrant containing the embedding vector and associated metadata for retrieval and search operations.

### Attributes:
- `id` (string): Unique identifier for the record in Qdrant
- `embedding_id` (string): Reference to the EmbeddingVector
- `payload` (object): Additional metadata stored with the vector in Qdrant
  - `text_chunk_id` (string): Reference to the source TextChunk
  - `source_url` (string): Original URL of the content
  - `source_location` (string): Location within the book
  - `book_title` (string): Title of the book
  - `book_author` (string): Author of the book
- `created_at` (datetime): Timestamp when the record was stored in Qdrant

### Validation Rules:
- `embedding_id` must reference an existing EmbeddingVector
- `payload` must contain all required metadata fields
- The vector must be properly indexed in Qdrant

## Relationships
- BookContent (1) → TextChunk (Many): A book content can be split into many text chunks
- TextChunk (1) → EmbeddingVector (1): Each text chunk generates one embedding vector
- EmbeddingVector (1) → VectorDatabaseRecord (1): Each embedding vector is stored as one record in Qdrant

## State Transitions
- BookContent: NEW → EXTRACTED → PROCESSED → CHUNKED
- TextChunk: CREATED → CLEANED → EMBEDDED → STORED
- EmbeddingVector: REQUESTED → GENERATED → VALIDATED → INDEXED
- VectorDatabaseRecord: PENDING → STORED → INDEXED → SEARCHABLE
